Why LookUI

Built for plain JavaScript — not in spite of it

Most UI kits assume a framework underneath. LookUI assumes nothing: it's a set of factories that bind to the markup you already have, in whatever stack you already run — server-rendered MVC, a CMS theme, a jQuery-era page, or a modern bundler.

Any stack, no framework

Vanilla JS and CSS — no React, Vue or Angular runtime to install or keep in sync. Call a factory on your own element and it works.

No build step required

One <link> and one <script> is a complete install. ESM and CommonJS builds are there too when you do use a bundler.

Localization is core

Every label, placeholder and message in every component routes through Look.i18n — translate one field or a whole app, with live locale switching.

Every action is overridable

before<Action> guards and lk:before-* DOM events let you veto, delay or rewrite what a click, drop or submit is about to do — no forking required.

Validation & a11y built in

Rules, async rules and server-error mapping ship with every form control; keyboard navigation, ARIA roles and focus traps ship with every interactive one.

One convention, everywhere

Learn onChange(value, ctx), destroy() and the guard pattern once — they work the same on every one of the 90+ pieces in the library.

How that compares to a typical framework-bound component library:

Quick start

No build step and no dependencies

1 · Install

npm install @lookui/core

…or load it from a CDN (pin the version in production):

<link rel="stylesheet" href="https://unpkg.com/@lookui/core@0.3.0/dist/look.min.css">
<script src="https://unpkg.com/@lookui/core@0.3.0/dist/look.min.js"></script>

2 · Include

<!-- classic script: exposes window.Look -->
<link rel="stylesheet" href="node_modules/@lookui/core/dist/look.css">
<script src="node_modules/@lookui/core/dist/look.js"></script>
// bundlers / ES modules
import '@lookui/core/look.css';
import { lkTextbox, lkDropdown, lkValidation, lkToast } from '@lookui/core';

3 · Markup + factories

<form id="signup">
  <input id="email">
  <select id="plan"></select>
  <button class="lk-btn lk-btn--primary">Sign up</button>
</form>

<script>
  const email = Look.lkTextbox('#email', {
    label: 'Email', name: 'email', rules: ['required', 'email'], validate: true,
  });
  const plan = Look.lkDropdown('#plan', {
    label: 'Plan', name: 'plan', required: true,
    items: [{ value: 'free', label: 'Free' }, { value: 'pro', label: 'Pro' }],
  });
  const form = Look.lkValidation(email, plan);

  document.getElementById('signup').addEventListener('submit', (e) => {
    e.preventDefault();
    if (form.validate().hasError) return;
    Look.lkToast({ type: 'positive', title: 'Welcome!', message: email.value });
  });
</script>

4 · Clean up

Every factory returns a plain object. Its owner (your controller / page script) calls destroy() when the markup goes away; composables also have close() / hide().
