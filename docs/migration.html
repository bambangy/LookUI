Upgrading to 1.0 / 0.3 / 0.4

The API freeze, plus the 0.3/0.4 callback convention — what changed and how to update your code

1.0 — the API freeze (breaking)

1.0 ships every component/composable listed in the catalog on the one callback convention below, plus localization and overridable events, and removes the three 0.3 compatibility shims that warned-but-worked until now:

RemovedUse instead
lkModal(triggerElement, modalElement)lkModal(modalElement, { trigger: triggerElement })
lkChip option onSelect (also inside lkToolbar chip items)onChange
lkPagination option onPageChangeonChange

Calling the library with any of these now does nothing (no warning, no shim) — search your codebase for the old names before upgrading. Everything else in 0.3/0.4 below is unchanged at 1.0.

0.4 — localization and overridable events (additive)

0.4 breaks no 0.3 code. Two conventions were added to every component and composable:

  • Text: all built-in English now lives in Look.i18n. Translate a page with Look.i18n.set('id', {…}); Look.i18n.use('id') or one component with { text: {…} }. Existing text options (placeholder, loadingText, noRecords, …) still win. See Localization.
  • Events: before<Action> options and lk:before-<action> DOM events can cancel, delay or replace an action. Legacy veto callbacks (onSave, onConfirm, chip onRemove, beforeChange of lkTabs) work as before. See Overridable events.

Things to check when you upgrade: lkDate / lkTable / lkToolbar now format with Look.i18n.locale (default 'en') instead of en-US / the browser locale — call Look.i18n.use(navigator.language) to keep browser-locale formatting; lkValidation.submit() reports 'Something went wrong' instead of null for message-less errors; code that located lkPagination buttons by aria-label should use [data-nav].

The convention

0.3 makes callbacks predictable before the 1.0 API freeze. Every component now follows the same four shapes:

KindShapeNotes
Value changesonChange(value, ctx)ctx is always an object with source (what caused it: 'select', 'click', 'key', 'api', …), component (the instance) and component-specific extras (item, prev, tab, …).
Open / closeonOpen(component) · onClose(reason, component)
onShow(component) · onHide(reason, component)		The instance is always passed.
Load / erroronLoad(el, ctx) · onError(error, ctx)Tabs and carousel content.
ClicksonClick(event, { component, … })Button, chip, toolbar items.

Complex components (lkTable, lkToolbar's onAction) keep a single event object, which now also contains component.

onChange fires for user actions. Setting value / checked / page from code is silent, except where a method says otherwise (lkDate.setValue(v, source), the pagination page setter report source: 'api').

Tip: use ctx.component instead of the variable you assigned the component to — some callbacks (e.g. lkList's onToggle with origin: 'init', carousel/tab content loading) can run while the factory is still returning, before your variable exists.

What still works

Everything below whose arguments changed in 0.3 cannot be detected automatically — update those callbacks when you upgrade. The three renamed-option shims that used to keep old names working are gone as of 1.0 (see above).

Before / after

0.2

Look.lkDropdown('#city', {
  items,
  onChange(value, item) {
    label.textContent = item.label;
  },
});

0.3

Look.lkDropdown('#city', {
  items,
  onChange(value, { item, source }) {
    label.textContent = item ? item.label : '';
  },
});

0.2

Look.lkTabs('#tabs', {
  tabs,
  onChange(name, prevName) {
    track(prevName, name);
  },
});

0.3

Look.lkTabs('#tabs', {
  tabs,
  onChange(name, { prev, source }) {
    track(prev, name);
  },
});

0.2

const modal = Look.lkModal('#open', '#dialog');
toolbar = Look.lkToolbar({
  items: [{ id: 'save', type: 'button',
    onClick(item, tb, e) { save(); } }],
});

0.3

const modal = Look.lkModal('#dialog', { trigger: '#open' });
toolbar = Look.lkToolbar({
  items: [{ id: 'save', type: 'button',
    onClick(event, { item }) { save(); } }],
});
