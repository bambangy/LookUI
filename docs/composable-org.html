Composable Org

Look.lkOrg(target, opts) — an organization chart: CEO → managers → reports, drawn as connected boxes, with CRUD, drag-and-drop re-parenting and a view-only mode

Interactive — add / edit / delete + drag-and-drop

Hover a card for its add-report / edit / delete actions. Dragging a card onto another card's row re-parents it (including onto a card with no reports yet — the empty row below it becomes a drop target while a drag is active); dragging it between two siblings reorders it. Every node is a real { id, parent, head, tail, prev, next, childCount, data } record — open the console and try org1.get('ceo').head.next.data.title.

—

View-only (readOnly: true)

Same data, no add/edit/delete affordances and no drag — but expand/collapse and clicking a card to select it (e.g. to show a detail panel) still work.

Guards — beforeMove enforcing a business rule

This chart's beforeMove rejects any attempt to re-parent the CEO, and the log below records every attempt. Try dragging the CEO card onto another card (rejected by the app's own rule) and try dragging a manager onto one of their own reports (rejected automatically — lkOrg prevents cycles regardless of beforeMove). Both go through the exact same guard path as org.move().

—

JavaScript

const org = Look.lkOrg('#chart', {
  items: [{ id: 'ceo', title: 'Jane Doe', subtitle: 'CEO', children: [
    { id: 'vp-eng', title: 'Sam Lee', subtitle: 'VP Engineering', children: [
      { id: 'eng1', title: 'Ann', subtitle: 'Engineer' },
    ] },
  ] }],
  onMove(node, ctx) { console.log(node.id, 'moved under', ctx.toParentId); },
  onChange(items, ctx) { console.log(ctx.action, items); },
});

org.get('ceo').head.data.title;       // 'Sam Lee' — real linked pointers, not an array facade
org.add('vp-eng', { title: 'New hire', subtitle: 'Engineer' });
org.move('eng1', { parentId: 'ceo', index: 0 });
org.remove('vp-eng', { strategy: 'promote' });   // vp-eng's reports move up to the CEO
org.destroy();
